- Convert [`src/app/sandbox/data-lab/template-particles/ui/page.tsx`](src/app/sandbox/data-lab/template-particles/ui/page.tsx) from page-local fetch and selection state into a reusable self-contained picker package following [`src/components/pickers/.docs/self-contained-picker-pattern-guide.md`](src/components/pickers/.docs/self-contained-picker-pattern-guide.md).

### Work Done

- Added UI-only query key in [`src/lib/api/query/query-keys.ts`](src/lib/api/query/query-keys.ts): `queryKeys.ui.templateParticlePickerSelectedId`.
- Created new package [`src/components/pickers/template-particle/`](src/components/pickers/template-particle/) with:
  - `_consts/query-keys.ts`, `_consts/index.ts`
  - `_hooks/use-template-particle-picker-selection.ts`, `_hooks/use-template-particle-picker-list.ts`, `_hooks/index.ts`
  - `_utils/template-particle-label.ts`, `_utils/resolve-selected-template-particle-id.ts`, `_utils/index.ts`
  - `template-particle-select-picker.tsx`, `template-particle-card-picker.tsx`, `template-particle-picker-detail.tsx`
  - `index.ts` public exports
- Refactored [`template-particles/ui/page.tsx`](src/app/sandbox/data-lab/template-particles/ui/page.tsx) into a thin consumer:
  - kept page shell, endpoint copy, refetch control, loading/error/empty states
  - replaced inline selection UI with picker components
  - removed page-owned `useState`, `useMemo` fallback/selection lookup, local label helper, and inline select/card/detail logic
- Verification completed in-session:
  - `ReadLints` on touched files returned no diagnostics
  - `npm run typecheck` passed

### Decisions

- Followed the established picker architecture: shared selection stored as `string | null` in TanStack Query UI cache via a dedicated `queryKeys.ui` key, with fallback resolution inside the picker list hook.

### Results

- `template-particles` selection logic is now portable and reusable outside the sandbox page.
- Select, cards, and detail stay synchronized through one picker state source while preserving prior behavior.
