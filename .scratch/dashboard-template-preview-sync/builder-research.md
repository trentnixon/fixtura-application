# Dashboard and template builder preview parity research

Research only, 2026-09-07. This note traces checked-in application code and the CMS handoff contract. It does not establish what the deployed CMS currently returns. No application code was changed.

## Recommendation

Keep the existing shared Account Remotion Preview assembly. Complete and normalize its saved input so dashboard previews receive the same effective design as the builder after save. Do not copy builder components into the dashboard or replace the Remotion bundle as the first fix. The code already shares both assembly and renderer. The strongest confirmed mismatch is the builder's separate account-photo selection; other likely gaps depend on the actual saved branding response.

## What the builder actually previews

The builder fetches account branding, media library, settings, organisation context, sponsors, mode UI catalog, texture UI catalog, public category catalog, and aggregate template options. It finds the saved template-option ID from account/me first and branding second, and includes that ID in the aggregate catalog request. See [builder data loading](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/template-builder-content.tsx:139>).

The editor maps `currentSelection` relation IDs to editor state. Animated selections require an additional lookup by numeric relation ID, then preset ID, to construct `{ ...defaultConfiguration, type: presetId }`. Therefore a reopened builder is still showing a catalog-expanded draft, even before the user changes anything. The editor replaces its draft whenever the hydrated saved state changes. See [hydration](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/template-builder-editor.tsx:281>), [relation mapping](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-editor-state.ts:77>), and [animation resolution](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-animation-catalog.ts:51>).

Once catalog and draft exist, the preview source is `kind: "draft"`, carrying branding, draft, aggregate options, public categories, UI texture catalog, and selected account photo. The temporary fallback is `kind: "saved"` with branding alone. See [preview source](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/template-builder-content.tsx:401>).

The preview panel calls the shared `useRemotionAssetPreview` and `AssetPreviewStage`. It chooses a cricket example composition from the asset picker, falls back to the default composition, fetches account sponsors, and defaults to thumbnails. Matching the builder includes matching this example composition and frame selection, as well as template inputs. See [preview panel](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_components/template-builder-preview-panel.tsx:60>).

## Current design options

The visible editor has four groups: template style, color pairing, contrast, and background. Current writeable backgrounds are Solid, Gradient, Video, Image, Texture, and Animated. Graphics, Particle, Pattern, Noise, and Generated are legacy read-only modes, despite some remaining generic picker code. See [write/read enums](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/types/api/template-options.ts:1) and [visible panels](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/template-builder-editor.tsx:634>).

| Option         | Data needed to reproduce the builder                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Template style | Category ID, slug, fixture division, and category metadata                                                                     |
| Color pairing  | Selected palette ID and palette value, applied to account branding colors                                                      |
| Contrast       | Selected mode ID and slug                                                                                                      |
| Gradient       | Gradient type and direction                                                                                                    |
| Image          | Image treatment preset: animation type/direction, overlay style, gradient type, overlay opacity; plus a separate account photo |
| Texture        | Texture media URL, opacity, blend mode                                                                                         |
| Video          | Position, size, loop, muted, offthread, volume, rate, overlay; actual media must also come from the render input               |
| Animated       | Numeric relation ID resolved to preset ID and catalog default configuration                                                    |

The option DTOs define these fields directly. See [catalog DTOs](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/types/api/all-template-options.ts:97) and [animation catalog DTO](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/types/api/all-template-options.ts:44).

## Save and reload behavior

Saving sends category ID, mode ID, palette ID, background mode, and all relevant relation IDs. Inactive background relations are nulled. It sends `templateAnimationId` for Animated, and deliberately does not send `animation` JSON. Category, mode, and background are required. See [save mapping](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-save-payload.ts:47>) and [background clearing](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-field-visibility.ts:65>).

This animation behavior follows the CMS handoff: accounts store a link to a preset; the linked catalog row supplies render defaults. The absence of animation JSON in the PUT body is intentional. See [CMS animation contract](/D:/htdoc/Fixtura/Fixtura.com.au/application/.comms/handoff/2026-08-28-app-handoff-animated-backgrounds.md:105).

Successful saves invalidate account/me, all aggregate-options queries for the account, then account branding. A dashboard parity issue should not be assumed to be missing save invalidation. See [mutation hook](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/lib/api/hooks/account/usePutTemplateOptions.ts:16).

## Concrete parity boundaries to preserve

1. Animated previews are expanded from the catalog inside builder hydration. A consumer using saved branding alone needs equivalent preset configuration already present in branding, or must resolve the saved relation against the catalog. Missing catalog presets produce `animation: null` in builder hydration rather than silently choosing a replacement. See [animation resolution](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-animation-catalog.ts:51>).

2. The chosen preview photo is local React state keyed by account. It defaults to the first media-library item and is absent from the save body. Exact photo parity after navigation cannot be promised from template persistence alone. Use the same deterministic sample-photo rule across previews, or deliberately add a persisted preview preference if exact photo continuity is required. See [local selection](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/template-builder-content.tsx:182>), [photo fallback](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-media-preview.ts:23>), and [save body](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-save-payload.ts:65>).

3. Texture previews prefer a separate UI catalog. That adapter normalizes opacity and resolves relative media URLs using the public Strapi URL. Aggregate-catalog fallback is used if the UI catalog request fails. Saved consumers need equally complete texture fields and compatible URL handling. See [texture loading](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/template-builder-content.tsx:300>) and [texture normalization](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-texture-catalog.ts:29>).

4. Legacy background modes intentionally become an unset builder draft requiring migration. A saved preview should preserve legacy read compatibility rather than blindly applying write-mode normalization, which could make existing accounts look different just by opening a page. See [state normalization](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/_utils/template-builder-editor-state.ts:84>).

5. A confirmed empty media library clears Image mode in the editor draft. That is separate from any already persisted Image setting. Saved-vs-draft comparisons must account for this intentional warning state. See [empty-library handling](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/template-builder/template-builder-editor.tsx:487>).

## Dashboard findings

The dashboard loads branding, categories, and modes, then passes `{ kind: "saved", branding }` to the same hook as the builder. Saved input goes straight to the shared merger; draft input first expands catalogue selections into branding. Both use `FixturaTemplateScene` from the same active `src/vendor/fixtura-remotion-assets/preview` import. See [dashboard data](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/dashboard/dashboard-content.tsx:69>), [saved source](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/dashboard/_components/dashboard-asset-preview-panel.tsx:76>), and [assembly branches](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/features/remotion-asset-preview/utils/assemble-account-remotion-preview.ts:58).

The shared merger already handles category, brand colours, contrast, palette, gradient, background assets, account logo, and sponsors. Category-ID hydration is already present. Background readers support Texture, Graphics, Image, Video, Particle, and Animated. This is not a dashboard with no support for the newer fields; it is a saved-input completeness and consistency question. See [merger](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/features/remotion-asset-preview/utils/merge-account-branding-into-dataset.ts:95) and [background readers](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/features/remotion-asset-preview/utils/read-remotion-background-assets-from-branding.ts:348).

## Proposed implementation sequence, not implemented

1. Capture the same account's branding response, aggregate currentSelection, and relevant catalogue entries. Compare the builder's assembled data immediately before save with the dashboard's assembled data after refetch. Hold composition, frame, logo, sponsors, and sample media constant. This identifies whether missing configuration belongs in the CMS response or the client resolver.
2. Define one resolved saved design input in `features/remotion-asset-preview`, independent of editor state. Prefer the documented expanded branding contract. Repair missing CMS fields there if confirmed; where relation-only input is intentional, resolve those IDs through shared catalogue helpers. Reuse the same defaults and URL/opacity normalization for draft and saved inputs.
3. Specify authoritative precedence for duplicated theme/template-option settings with the CMS contract. Retain account brand colours from the theme, and verify that saving template-builder mode/background cannot be overridden by stale duplicated values. Preserve legacy read support separately from builder write validation.
4. Supply the dashboard with account media using the same sample-photo rule. If the exact manually selected builder photo must survive navigation or reload, introduce an explicit persisted preview preference. The current templateImageId identifies image treatment, not that selected photo. Unsaved design changes should remain in the builder; parity means the last successfully saved design unless product scope changes.
5. Add parameterized draft-to-saved assembly comparisons for all six current backgrounds, categories, palettes, and contrast modes. Include missing/deleted catalogue rows, old theme conflicts, no media, legacy modes, and inactive-background clearing. Then compare real rendered frames and video at the same time point, and verify save, navigation, reload, and account switching.

Use a loading/error state while required saved-preview input is unresolved, instead of presenting demo defaults as the user's finished design. Extend the existing shared feature so future account previews can consume it without importing template-builder route internals.

## Other preview locations and limits

The production member callers of `useRemotionAssetPreview` found in this checkout are dashboard and template builder. The interaction-lab Remotion route uses a separate sandbox dataset merger and direct preview components. It should remain an explicit demo consumer unless account-specific previewing is intended. The older dashboard branding-summary component uses a poster/logo URL, and is not mounted by the current dashboard content. Those static assets cannot acquire live customization simply by sharing the renderer. See [sandbox loader](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/sandbox/interaction-lab/remotion/_hooks/use-remotion-sandbox-preview-data.ts:1) and [older summary](</D:/htdoc/Fixtura/Fixtura.com.au/application/src/app/(members)/o/[accountId]/dashboard/_components/dashboard-branding-summary.tsx:25>).

The shared account loader currently supports Cricket example datasets only. It previews account design on sample sporting content, not the account's actual fixtures or previously rendered videos. See [dataset loader](/D:/htdoc/Fixtura/Fixtura.com.au/application/src/features/remotion-asset-preview/utils/example-dataset-loader.ts:19).
